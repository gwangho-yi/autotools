# 다중 감지점 중 하나 선택 (덩어리 중앙 + 우선순위/랜덤) 설계

## 목표
감시 영역 안에서 감지점(변화/색일치)이 **여러 군데 흩어져** 나타날 때, 지금처럼
전체 픽셀의 평균(centroid)을 찍어 **엉뚱한 빈 공간**으로 가는 버그를 없애고, 사용자가
정한 규칙으로 **감지된 좌석(덩어리) 하나를 정확히 그 중앙에** 클릭하도록 한다.

## 배경 — 현재 버그
`monitor.py`(변경 감지)와 `color_monitor.py`(컬러 감지) 모두 감지 판정 후
`xs.mean()/ys.mean()`으로 **매칭 픽셀 전체의 무게중심**을 클릭 좌표로 삼는다. 감지점이
여러 개로 흩어지면 그 평균은 점들 사이의 빈 곳이 되어, 감지되지 않은 지점을 클릭한다.
(참조: `docs/bug-reports/2026-08-01-known-bugs.md` 버그 #1)

## 설계 결정 (확정)

### 1. 선택 단위 = "덩어리 중앙"
- 매칭 픽셀들을 **연결된 덩어리(좌석 단위)로 묶고**, 고른 덩어리의 **중심 좌표**를 클릭한다.
- 가장자리 픽셀이 아니라 중앙이라, 좌석 클릭 판정 영역 안쪽에 안전하게 떨어진다.
- 이 "덩어리 목록" 위에서 우선순위·랜덤이 모두 일관되게 동작한다.

### 2. 어느 덩어리를 고를지 = 우선순위 5버튼
UI에 버튼 5개: **왼쪽 / 오른쪽 / 위 / 아래 / 랜덤**.
- **방향 버튼(왼/오/위/아래)**: 누른 **순서가 곧 우선순위**다.
  - 예) "왼쪽 → 위" = 1순위 가로(가장 왼쪽), 2순위 세로(그중 가장 위)
  - 예) "위 → 왼쪽" = 1순위 세로(가장 위), 2순위 가로(그중 가장 왼쪽)
- **랜덤**: 덩어리들 중 하나를 **균등 무작위**로 선택(한 줄 영역처럼 방향이 무의미할 때 사용).
- 규칙:
  - 하나만 눌러도 동작(2순위 미지정 시 내부 기본값 사용 — 기본 2순위는 "위→왼쪽" 순의 미지정 축).
  - 같은 축의 반대쪽을 누르면 교체(예: 왼쪽 눌린 상태에서 오른쪽 누르면 오른쪽으로, 순위는 유지).
  - 방향 버튼과 랜덤은 상호배타(랜덤 누르면 방향 선택 해제, 그 반대도).
  - 선택 상태를 눈에 보이게: 누른 순서대로 **①②** 배지 또는 상단에 "왼쪽 → 위" 텍스트 표시.
- 기본값(앱 시작 시): **왼쪽 → 위** (좌상단 우선). 결정적이라 랜덤 아님.

### 3. 반응 속도 = INTERVAL 0.5초 → 0.1초
- 감시 루프의 `INTERVAL`을 0.5초에서 **0.1초**로 낮춘다.
- 실측 기준 한 사이클(캡처+비교+선택) ≈ 40ms라, 0.1초 주기로도 CPU 여유 충분.
- 변화/색 발생 시 최악 ~0.2초 내 감지.

### 4. 덩어리 묶기 = scipy 없이 numpy로
- 빌드 spec이 `scipy`를 제외(exe 용량)하므로 의존성 추가 없이 numpy만으로 연결 성분을 구한다.
- 좌석처럼 서로 떨어진 대상에 정확하고 가볍다. 한 줄(1D)·얇은 띠 영역은 특히 단순.
- 매칭 픽셀이 비정상적으로 많을 때를 대비한 가드(예: 다운샘플 후 묶기)를 둔다 — 성능 안전장치.

## 범위 밖 (이번 작업 아님)
- **여러 감시 영역 간 통합 선택**: 지금은 영역마다 독립 스레드가 각자 자기 영역 안에서 하나를
  골라 신호를 보낸다. "여러 영역이 동시에 떴을 때 화면 전체에서 딱 하나"는 **나중 과제**로 미룬다
  (감지 속도 우선). 즉 이번엔 **한 영역(한 스레드) 안에서의 선택**만 구현한다.
- 아키텍처(영역별 스레드 구조)는 그대로 유지한다.

## 동작 흐름 (한 스레드 = 한 영역, 매 사이클)
1. `sct.grab(region)` → `mask`(boolean H×W) 계산 (기존과 동일).
2. 매칭 픽셀 수 < 임계값(`MIN_CHANGED`/`MIN_MATCHED`) → 감지 없음 (기존과 동일).
3. **`mask`를 덩어리로 묶어** 각 덩어리의 중심(픽셀 좌표) 목록을 만든다.
4. **선택**:
   - 방향 우선순위 → 덩어리 중심들을 (1순위, 2순위) 축으로 정렬해 첫 번째.
   - 랜덤 → 덩어리 중 하나 무작위.
5. 고른 덩어리 중심(픽셀) → 화면 전체 좌표로 변환(`region.left + fx*width`, …).
6. 신호 발사 (기존 쿨다운 로직 유지).

## 컴포넌트별 변경 요약
- **감지 코어** (`apps/motion-capture/core/monitor.py`, `apps/color-capture/core/color_monitor.py`):
  centroid 평균 → 덩어리 묶기 + 우선순위/랜덤 선택. 생성자에 `priority` 파라미터 추가.
  `INTERVAL` 0.1로.
- **덩어리/선택 유틸**: 두 앱이 같은 로직을 쓰므로 `autotools_shared`에 공용 함수로 두는 것을 권장
  (예: `autotools_shared/detection.py`의 `select_target(mask, priority) -> (cx, cy) | None`).
- **UI**:
  - motion-capture: 변경 감지 페이지(`apps/motion-capture/ui/launcher.py`)에 5버튼 우선순위 추가.
  - color-capture: `apps/color-capture/ui/color_capture_tab.py`에 5버튼 우선순위 추가.
  - 선택된 priority를 스레드 생성 시 전달.

## 우선순위 표현(내부)
- `priority`: `"random"` 또는 축-방향 순서 리스트. 각 원소는 `"left"|"right"|"top"|"bottom"`.
  - 예: `["left", "top"]`(왼쪽 1순위, 위 2순위), `["top"]`(위 1순위, 2순위는 기본값).
- 선택 로직: 리스트를 정렬 키로 사용(left=x오름, right=x내림, top=y오름, bottom=y내림)해
  덩어리 중심들을 사전식 정렬 → 첫 번째. `"random"`이면 무작위.
- 2순위가 없으면 기본값으로 보완(미지정 축을 top→left 순으로 채움).

## 구현 순서
1. **motion-capture 먼저** 구현·검증(오케스트레이터 macOS 실행/스크린샷).
2. 동일 패턴을 **color-capture**에 적용.
3. 공용 선택 로직은 shared로 추출해 두 앱이 공유.

## 테스트 전략
- shared의 `select_target` 단위 테스트: 흩어진 여러 덩어리 mask를 만들어
  각 우선순위(왼/오/위/아래 조합, 랜덤)에서 기대한 덩어리 중심이 나오는지 검증.
- 각 앱: UI 우선순위 위젯의 상태 전이(누른 순서, 교체, 랜덤 배타) 테스트.
- 런타임: 오케스트레이터가 실제 화면에서 여러 감지점 상황을 만들어 확인.
